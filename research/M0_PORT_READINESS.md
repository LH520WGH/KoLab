# KoLab M0：Gloomy 设备加载机制移植准备度审查

本文件依据同分支的 `GLOOMY_LOADING_EVIDENCE.md`（DSH Go 报告，390 行）整理，是工程分析与验收矩阵，**不代表加载机制已经移植成功**。项目主程序仍是 0.2 Binder/只读预检原型。

## 核验结论

| 项目 | 当前判定 | 证据位置 | 工程影响 |
|---|---|---|---|
| Gloomy 的 Root 引导与第三方 .ko 加载分离 | 已由静态控制流支持 | 报告 §3–5 | 不能直接把 exploit-vivo 的 KernelSU 引导当作通用模块加载 API |
| Java 用户模块加载入口 | 已由静态控制流支持 | §5, J:758–840 / S:4649–5249 | 可以重建入口/返回码模型，但不等于复现有效后端 |
| 厂商 BSP 检查与摘要写入 | 存在静态路径；实际作用未被实测闭合 | §5.2, §7 | 不可把一次写入或固定门值等同于通行许可 |
| 外部 Kairos loader 的贡献 | **未知**，报告所见目标路径当前不存在 | §6 | 不能把历史成功归因于 Java insmod；需原件与日志 |
| Native `kw_load_now` | 存在 init/finit_module 路径，主要围绕 kernelsu | §7 | 不能当作任意用户模块通用 API |
| 历史 KAIROS 模块处于 Live | 有历史快照 | §9.1 | 不能证明来自哪个文件、哪个加载方法或哪个时间点 |
| Vivo 设备与内置模块兼容性 | 只有部分内核前缀/不同 vermagic 数据 | §8 | 需要完整 release、符号 ABI、KMI、内核配置、签名策略分别核验 |
| KoLab 0.2 跨应用 Binder | 真机截图已显示授权后可获得 capabilities JSON | 已有 KoLab Bridge 测试 | IPC 基础可复用；`loadModuleSupported=false` 是真实状态 |
| KoLab 独立加载后端 | **未完成** | §11–12 | 不生成宣称可刷入驱动的最终版 |

## 当前明确的不充分证据

1. Gloomy 目标模块输入完整哈希和内核里已存在模块的二者绑定。
2. 同一次尝试的加载前状态、真实调用结果/errno、同次 boot 的内核事件和加载后状态。
3. 外部 Loader 是否曾执行、正文内容、执行时是否替换过模块镜像。
4. BSP 厂商安全状态的精确语义和不同条件下的有效性边界。
5. 功能级验收：设备在加载后是否真的出现预期的驱动功能；单纯模块名或进程成功码不充分。

## 下一阶段工程任务：先证明，再移植

### M0A — 证据一致性
- 核对样本哈希；报告中的绝对 DSH Go 路径仅指向手机本地，GitHub 在线阅读时不可打开。
- 逐条映射 Java→Smali→Native 的静态调用证据；所有无法从现有文件证明的边标 `UNKNOWN`。
- 用导出表区分“模块当前存在”“本次新加载”“用户功能可用”。

### M0B — 只读设备可观测性
- 设计一份只读的结构化状态报告：Android build、完整 uname release、模块列表及只读可读取的安全配置。
- 设备本机可得到并不代表 KoLab App 有权限读取；需要记录实际 UID、SELinux 域及读取失败原因。
- 不自动重放利用脚本、不执行不明 .sh，不修改 BSP / SELinux，不卸载/加载任何模块。

### M1 — 可维护的设备适配后端（尚未具备实施前提）
- 先从已获授权的设备/内核文档确认允许的模块加载方式；不能把厂商策略绕过步骤当作既定 API。
- 将 IPC 与执行器分开，入口只接受单个模块的不可变文件句柄和 SHA-256，不接受任意命令、脚本或全路径写入请求。
- 调用前检查类型、ABI/vermagic、签名政策及已存在状态；关键条件不满足就返回可解释的 `UNSUPPORTED`。
- 后端成功与否应由具体进程结果、内核记录及功能测试共同决定，不把界面 Toast 或 stderr 文本当作证据。

## 统一验收状态

`BRIDGE_READY_READ_ONLY` → `DEVICE_PRECHECK` → `BACKEND_UNVERIFIED` → `AUTHORIZED_ATTEMPT` → `LOADED_NEW` / `ALREADY_PRESENT` / `LOAD_FAILED` → `FUNCTIONAL_VERIFIED`

任何状态与原始证据不相符时须回到 `UNKNOWN`；尤其已存在模块不能当成新加载成功。

## 对用户交付的说明

- 当前 KoLab 0.2 可作为 IPC/授权/分析基础版测试，不是最终驱动加载版。
- 报告完整上传到独立研究分支，不覆盖 main。
- 研究报告所引用的 `/root/workspace`、`/sdcard` 为原设备本地路径，需要保留源归档才能进一步校验。
- 后续可建立官方可审查的内核兼容加载路径；无法由此报告直接证明任何 Vivo 安全机制已被独立解除。
